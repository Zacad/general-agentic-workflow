# Produce an outcome

**Inputs:** authorized unit and matching revision, current justified-leaf Work split, inherited decisions, linked accessible own-unit investigator report set and assigned planner integration basis, available research, explicit owned output paths and attempt path.

The investigator/report/finer-boundary references below mean the applicable primary set and integrated whole-unit sizing basis per protocol. Actually read those reports, material cited evidence and integration for this commitment; sufficient union coverage does not require each narrow report to prove the whole unit. Summary assertions/counts cannot substitute. Retain fresh unaffected dimensions and renew only material affected questions/interactions with explicit retained/revalidated/replaced applicability and gaps/owner/action/dependency impact. Scoped blocking does not bypass full discussion fail-closed or selected-level group readiness. Carry the same set/identity/applicability links into stable-target independent checking.

**Procedure:**
1. Verify the parent/root checkpoint names this unit's current revision; read the linked own-unit investigator report and check current applicability per protocol before deliverable work. Self-research/skill loading, assertions or another unit's report cannot substitute. Stop missing/inapplicable coverage, contradictions or changed material uncertainty/dependencies for renewed distinct same-unit investigation, retaining/linking prior evidence; refreshed evidence cannot override authorization/decisions. Inspect existing outputs before editing. Respect all constraints and output ownership.
   Consume its current Work split and investigator's finer-boundary assessment: one adequate completion/review/check horizon with manageable dependencies and a specific reason finer splitting adds coupling rather than useful independent acceptance/retry. A leaf label, generic smallness or split unknown is insufficient. If changed scope/evidence invalidates sizing, stop affected delivery and return the gap through renewed same-unit investigation, assigned planning/preparation and reconciliation per protocol. Do not silently create/enter children or edit unowned briefs; actual material revisions require matching revised checkpoints, while unrelated authorized work may proceed.
   Before dependent delivery, consume applicable current requirements/coverage and actual review readiness per protocol (linked map or concise sourced leaf statement). Each material acceptance item must trace to sufficiently agreed current scope or applicable approved brief/D authority, expected content/outcome/depth and a suitable check; inspect all requested dimensions and open dependencies, not just planned outputs. Missing material coverage/agreement/feasibility stops only affected delivery/claims: report question, owner/action and route evidence gaps through renewed own-unit investigation and assigned preparation, material changes through existing revision/D/checkpoint gates. Do not invent exclusions, agreement or unowned brief edits. An authorized discovery outcome can finish as a draft/open review handoff without claiming dependent readiness; use `endeavor-requirements` for substantial nonsoftware discovery and retain software `product-requirements` specialization.
   For affected substantial software delivery with material testing commitments, consume the exact applicable sufficiently reviewed strategy/critical coverage/feasibility basis per protocol and `choose-approach`/`code-architecture`, including concrete state/input, check level/method, expected observable, evidence/limits, version/prerequisite status and actual presented scope/version/response. Reuse adequate specifically reviewed unchanged strategy, or concise focused-issue approved acceptance/meaningful regression/honest limits; no forced strategy unit, token alternatives or runner microapproval. A stored unseen plan, generic architecture approval or partial reply cannot settle unreviewed clauses/v2 additions. Missing material coverage/review/prerequisites stops only affected delivery/claims with exact question/owner/action; route evidence/material changes through existing own-investigation/preparation/D/revision gates, retaining unrelated authorization. Feasible sufficiently agreed future checks can remain planned-unrun before app code; nonexecution alone does not block build authority. Strategy approval/build/HTTP/mocks do not prove browser/storage/recovery/learning execution. Preserve check independence: the verifier may add necessary failure-detecting checks beyond the plan. Executable teaching consumes fitting reconstruction/runtime/correct-reason checks with learner limits; pure prose/travel consumes domain-source/scenario checks.
   Before affected material UI production, consume the protocol's sufficient reviewed direction/assets/constraints/**actual scoped response** or validated adequate reviewed unchanged reuse/tiny basis, not retrospective expert-as-user preference. Trace affected acceptance to exact review statements/version/presentation/assets/states/widths/platform and suitable checks/dependencies; pending/partial/declined or inaccessible visuals do not agree the remainder/future v2. Load `ui-ux-design` early for material exploration; discovery may deliver a truthful open handoff, but affected material delivery waits with question/owner/action while unrelated authorized work continues. Tiny in-direction label/focus/semantic-role corrections need concise sourced acceptance/focused checks, not two token options/brand tree/microapproval; file count does not excuse new direction. Review does not authorize unnamed children/material changes; preserve existing D/revision/checkpoint gates and delegated routine refinement.
   Hand the independent checker stable delivered UI plus exact reviewed direction/assets/response and fitting states/widths/hierarchy/type/color/layout/identity/action-priority/interaction-responsive criteria to flag material unreviewed drift. Keep aesthetic hypotheses, actual preference, objective functional/rendered/accessibility results and participant/task/method/results studies separate; mockup approval proves no final geometry/keyboard/AT/reflow/full WCAG or user/learner outcome. Preserve required execution checks independently of direction comparison.
   Before dependent delivery consume the protocol's selected-group preparation basis in the coordinating Work split/Relationships: actual bounded user selection after adequate requirements/appropriate structure, sibling-level wave evidence and every selected path's evidenced justified-leaf or explicit deferred/blocked disposition (reason, owner/action, dependency impact, reconsideration basis). A local leaf's checkpoint/state or taxonomy label cannot bypass unfinished group preparation; report affected gaps to the assigned writer. Authorized discovery/requirements/structure/preparation outputs establishing readiness are exempt from this barrier, while their own authority/evidence/criteria still apply. Independently acceptable modules/infrastructure are valid alongside vertical slices. Parallel delivery requires reconciled group readiness, settled dependencies and disjoint outputs. Do not expand unrelated branches, invent task units or update unowned group state. Changed requirements/evidence reopen affected readiness through the existing investigation/preparation/material-authority gates.
2. Create the smallest complete deliverable that meets the unit's criteria. Iterate with proportionate local checks; consult a specialist skill when a domain demands it.
3. Preserve concurrent workers' work. Document changed output paths, actual checks/results, limitations, and any gap against criteria in the attempt report.
4. Hand off a stable named output/attempt for independent checking.

   Supply a stable output/source manifest with complete target identity and published variant/producer attempt, approved criteria/applicable requirements/decisions and exact current review statements/version/response, consumed own-unit investigator report/applicability, and reproducible published instructions/environment. For executable teaching include student-visible files/support, imports/exports/entry point, exercise/actual solution edits, commands/cwd and pinned runtime/framework/dependency/browser prerequisites. For domains supply applicable sources/dates and scenario/audience assumptions. Label producer selfchecks explicitly with actual commands/results/artifacts and limits; they are inputs, not an independent invocation or oracle. The assigned independent verifier owns its clean reconstruction/result/report/separate concise user-summary paths per protocol; it does not fix delivery gaps. Freeze the named sources during checking. A repair or any changed output names a new stable target for scoped independent checks, preserving prior failures; a repaired published solution needs a new distinct verifier. Do not represent required unrun/blocked runtime as PASS or attempt completion as unit verification. Actual user outcome-summary read/relay precedes authoritative outcome state update through the existing orchestrator route.

**Output:** assigned deliverable(s), own report, compact receipt per `.agents/workflow/protocol.md`.

**Stop/escalate:** no valid checkpoint, unjustified/invalidated leaf or meaningful further outcome boundary, ambiguous ownership, material new requirement, failed dependency, or conflict with an inherited approved decision. Return to the affected preparation/authority scope; do not broaden scope or weaken criteria to make checks pass.
