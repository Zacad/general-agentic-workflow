# Reconcile a unit

**Inputs:** unit/revision, verifier and producer attempt paths, criteria, applicable decisions, child outcomes where relevant, owned brief/decision paths.

Supply exact current approved criteria/subclaims and requirements/D/review statements/version/response, own-unit investigator/applicability, actual producer and distinct independent verifier invocation/report/compact receipt/result/short-summary links, target/baseline/source manifests, summary read/relay reference and assigned sole-writer/short reconciliation-summary paths per [protocol](../../workflow/protocol.md#artifact-grounded-authoritative-reconciliation). Reuse the existing criterion proof by link.

**Procedure:**
1. Compare checked evidence to each criterion and the parent's own outcome. A verified child is evidence, not automatic parent verification; provisional branches count only if required by parent criteria. Use a proportionate evidence standard: a recorded pre-work inventory/hashes and independently checked post-work output can support a bounded containment claim even when a Git diff is unavailable. Disclose what the evidence cannot prove; do not demand impossible proof of every intermediate filesystem write unless the approved criterion actually requires that audit.
   - **Actually open** the primary producer/deliverable/manifest, independent verifier invocation/report/receipt/result/summary and current source/approved authority. For each required criterion/subclaim independently compare identity/revision/target/variant/baseline, actual independence, source/current review applicability, expected result/method/environment/prerequisites, execution/observed artifact and limits using the linked proof trace. Report access and current criterion support are separate checks; do not rubberstamp PASS/conclusions.
   - Distinguish genuinely absent evidence from existing wrong-unit/revision/target/baseline or partial reports and from pending/blocked/contradictory primary results. Record each criterion disposition with basis/limits/owner-action. Valid current evidence can correct stale “no report/pending” prose: preserve the then-pending snapshot and explain the replacement, without inventing execution or rerunning a just-completed check. Required unverified/pending/contradicted stays unverified at unit level; partials cover the whole only on actual approved coverage. Check an actually approved fallback's exact scope, executed variant/evidence/limits; never invent fallback/exclusion or weaken acceptance. Unknown meaningful authority stops affected claims upstream.
   - For a parent, consume its own independent coverage/coherence/integration proof and reconcile each parent criterion; child verification alone cannot supply that check.
2. For gaps, choose a bounded retry, additional check, blocker, or return to an earlier decision level. Pause only units dependent on invalidated assumptions; identify impacted units and preserve previous rationale.
   Route repairs only to the assigned producer. Retain failed/incomplete/replaced reports/results and rationale/impacts; a changed output needs a newly named frozen target and an actual **new distinct independent scoped check**, with necessary affected interaction/regression checks. Moving-source mismatch invalidates current applicability, not old-result history. Recheck only changed or unresolved concerns; no broader repeat solely because checking completed. Material uncovered uncertainty needs renewed distinct same-unit investigation with retained evidence; material outcome/boundary/criterion/inherited changes pause affected work for matching revision/D-scope/checkpoint before advancement. Unrelated authorized work may continue.
   Reassess current Work split when changed scope/evidence exposes independent outcomes, uncertainty or dependencies: does the selected child horizon or justified leaf still fit actual completion/review/check/retry boundaries? Return material evidence gaps for renewed same-unit investigation, then assigned planning/preparation; unresolved sizing remains provisional with question/owner/action. Update the appropriate split/evidence summary only as assigned writer, retaining earlier rationale/impacts. Do not silently bundle newly independent outcomes, enter unapproved children or build a speculative hierarchy; unrelated authorized work may continue.
3. If assigned sole writer, update the authoritative brief's evidence links, state (`active`, `blocked`, `verified`, `stopped`) and next action. Preparing children alone is not automatically a material revision; actual outcome/boundary/criterion or consequential inherited changes increment revision and suspend affected advancement pending a matching new checkpoint (resolve inherited conflicts at their decision scope). Newly prepared or prospectively materially revised briefs require the complete reasoned Work split per protocol; proposed children still need explicit named current-revision checkpoints after preparation.
   Maintain its current complete meaningful `Decision log` per protocol from actual sources, worker-choice reports and checked evidence before claiming the brief current/complete. Incorporate settled local approach/check/split/dependency choices with status, scope, alternatives, concise rationale and source/actual authority; findings/recommendations and unapproved consequential changes stay separate proposals/open questions. Do not fabricate absent historical options/rationale or user motives; mark unknowns and label new comparisons/inferences. Retain superseded positions/rationale, replacements and impacted units, linking actual scoped D approvals and explicit approved exception/supersession; a newer/local summary cannot override D/checkpoints. Missing/conflicting material authority remains unresolved and stops affected claims/work upstream. Editorial log/link maintenance alone does not bump revision or create a phase checkpoint. If not assigned sole writer, report the needed update and meaningful choices for that writer; do not edit its brief or create a duplicate status store.
4. Tell the orchestrator what user decision or authorization is needed, if any.
   Before a current/complete or reconciled claim, **actually update** the owned criterion dispositions/primary links, state, complete meaningful Decision log, reasoned current Work split, history/impacts and one bounded next action under step 3. Report/receipt alone is incomplete; non-writers report needed edits to the sole writer. Write the separately assigned concise reconciliation summary referencing the actual updated authority/primary proof and limits/next action. Return the compact receipt so the orchestrator can actually read/relay this short artifact under its full discussion route, retaining identity/read-relay reference or pending owner/action. Do not duplicate authority or relabel the earlier verifier summary as later state reconciliation.

**Output:** reconciled brief when assigned, attempt report with criterion-by-criterion reasoning, compact receipt per `.agents/workflow/protocol.md`.

Link actual updated owned authority, reused primary criterion proof and separately owned concise reconciliation summary; distinguish completed writer edits from proposed updates and pending visibility.

**Stop/escalate:** inconclusive evidence needed for a success claim, missing verifier, or contradictory approved decision. Do not silently mark verified.
