# UI/UX design

**Inputs:** audience, tasks, use setting, platform and devices, desired
quality, brand assets, content, constraints, and the review artifact path.

## Procedure

1. Ask a few discriminating questions early: who uses it, for what task, on
   what device, in what state, and what quality or brand applies. Mark missing
   input as an assumption, not a user need.
2. Inspect the current interface, the task evidence, and primary platform or
   design-system guidance. Record source, version and date.
3. Map entry, decision, action, wait, empty, error and completion states.
   Define reading order, action priority and the most consequential failure.
4. For a material direction, compare two coherent options for the **same**
   tasks and content: hierarchy, layout, spacing, type, color, navigation,
   feedback, and narrow/wide behavior. Two palette swaps are not options.
5. Produce actual viewable representations with permitted tools. A textual
   description or raw HTML is not a rendered preview.
6. Cover semantic roles, contrast, focus, keyboard, zoom/reflow, error and
   status messaging, motion (with a reduced path) and responsive behavior.
7. Present the exact direction and retain the actual response. Mockup
   selection does not prove rendered geometry or accessibility.

## Output

A review artifact, assets and a report. Check actual composited contrast and
rendered states where the claim requires it; do not claim participant or
accessibility results you did not measure.
