# Source-to-rule map (checked 2026-09-30)

Use this map selectively; inspect the linked primary material anew when applying a rule, particularly for changed standards, components or jurisdictions. **N** = normative web-content success criterion *when the chosen WCAG 2.2 level applies*; **E** = W3C informative explanation/pattern; **S** = design-system or service convention limited to its context; **J** = proposed expert judgment, not sourced effectiveness. The examples below do not establish legal obligations, native-app standards, translation quality or full WCAG conformance. The WCAG Recommendation links errata; compare the current fixed edition/errata for formal audits.

## Web accessibility — normative criteria and explanatory scope

**N0:** W3C, [*Web Content Accessibility Guidelines (WCAG) 2.2*](https://www.w3.org/TR/WCAG22/), Recommendation **12 December 2024**, fixed edition `https://www.w3.org/TR/2024/REC-WCAG22-20241212/`, version 2.2, web content on any device; read SC and glossary at the fragment URLs below. Conformance levels A/AA/AAA differ; claims require full pages/complete processes and other conformance requirements. Supporting Understanding/Techniques are informative and may be updated separately. No native iOS/Android or non-web blanket application follows. **E0:** W3C WAI, [*Understanding SC 1.4.3: Contrast (Minimum)*](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), informative WCAG 2.2 Understanding, page updated **01 June 2026**; provides threshold/large-scale interpretation and sRGB formula, not an independent standard.

| Context-specific design check → precise source | Required outcome if applicable; informative/judgment boundary |
| --- | --- |
| Color, brand, charts: [N0 1.4.1 A](https://www.w3.org/TR/WCAG22/#use-of-color), [1.4.3 AA](https://www.w3.org/TR/WCAG22/#contrast-minimum), [1.4.11 AA](https://www.w3.org/TR/WCAG22/#non-text-contrast), E0 | Color not sole *visual* means of conveying an action/info; ordinary text/images of text >=4.5:1, large-scale >=3:1, with inactive/decorative/incidental/logotype exceptions. Required visual information identifying UI components/states or graphical meaning >=3:1 against adjacent colors, with SC exceptions. E0: logotype exception does not exempt all brand copy, thin unusual fonts can read faint despite computed pass. [1.4.6 AAA](https://www.w3.org/TR/WCAG22/#contrast-enhanced) is 7:1 ordinary, 4.5:1 large; do not call AAA required for AA. Compute *used* states and image overlays; no generic 3:1 decorative-border rule. |
| Type, layout, zoom: [N0 1.3.1 A](https://www.w3.org/TR/WCAG22/#info-and-relationships), [1.3.2 A](https://www.w3.org/TR/WCAG22/#meaningful-sequence), [1.4.4 AA](https://www.w3.org/TR/WCAG22/#resize-text), [1.4.10 AA](https://www.w3.org/TR/WCAG22/#reflow), [1.4.12 AA](https://www.w3.org/TR/WCAG22/#text-spacing) | Convey visual relationships programmatically or in text; reading sequence must remain correct when meaningful. Text resize up to 200% without content/function loss (captions/images of text exception); vertical scrolling content at width equivalent 320 CSS px without loss or 2D scrolling, except *parts* requiring 2D layout. Markup supporting spacing properties must survive override of line height >=1.5×, paragraph spacing >=2×, letter >=0.12×, word >=0.16× font size with no other property changed; **not default authored spacings**. No WCAG-mandated font family, two-thirds grid, or mobile breakpoint. |
| Interaction, focus, target: [N0 2.1.1 A](https://www.w3.org/TR/WCAG22/#keyboard), [2.1.2 A](https://www.w3.org/TR/WCAG22/#no-keyboard-trap), [2.4.3 A](https://www.w3.org/TR/WCAG22/#focus-order), [2.4.7 AA](https://www.w3.org/TR/WCAG22/#focus-visible), [2.4.11 AA](https://www.w3.org/TR/WCAG22/#focus-not-obscured-minimum), [2.5.8 AA](https://www.w3.org/TR/WCAG22/#target-size-minimum) | Keyboard operation with SC's underlying-path exception, escape from keyboard focus traps, meaningful focus sequence, visible keyboard focus, focused component not *entirely* obscured by author content; targets >=24×24 CSS px **or** spacing/equivalent/inline/unmodified-UA/essential exceptions. Hit area ≠ icon pixels. [2.5.5 AAA](https://www.w3.org/TR/WCAG22/#target-size-enhanced) is 44×44 CSS px; [2.4.13 AAA](https://www.w3.org/TR/WCAG22/#focus-appearance) is not AA. Need code/keyboard and viewport inspection, not a static frame. |
| IA, copy, languages: [N0 2.4.4 A](https://www.w3.org/TR/WCAG22/#link-purpose-in-context), [2.4.6 AA](https://www.w3.org/TR/WCAG22/#headings-and-labels), [3.1.1 A](https://www.w3.org/TR/WCAG22/#language-of-page), [3.1.2 AA](https://www.w3.org/TR/WCAG22/#language-of-parts), [3.2.3 AA](https://www.w3.org/TR/WCAG22/#consistent-navigation), [3.2.4 AA](https://www.w3.org/TR/WCAG22/#consistent-identification), [1.3.4 AA](https://www.w3.org/TR/WCAG22/#orientation) | Link purpose discernible in context, headings/labels *when present* describe topic/purpose, default human language and relevant language changes programmatically available (SC exceptions), repeated nav/order and same-function identification consistent across set of pages, no single orientation restriction unless essential. None specifies one correct sitemap, wording, hero image or tone. |
| Input, recovery, status: [N0 3.3.1 A](https://www.w3.org/TR/WCAG22/#error-identification), [3.3.2 A](https://www.w3.org/TR/WCAG22/#labels-or-instructions), [3.3.3 AA](https://www.w3.org/TR/WCAG22/#error-suggestion), [4.1.3 AA](https://www.w3.org/TR/WCAG22/#status-messages) | Automatically detected input errors identify item and describe error in text; input has needed labels/instructions; suggest known correction unless it risks security/purpose. In markup, actual status messages determinable to AT without receiving focus. Not every text change is a status, nor is a GOV.UK error summary a WCAG-required layout. |
| Motion: [N0 2.2.2 A](https://www.w3.org/TR/WCAG22/#pause-stop-hide), [2.3.3 AAA](https://www.w3.org/TR/WCAG22/#animation-from-interactions) | Qualifying automatically started movement/blinking/scrolling lasting >5s in parallel requires pause/stop/hide unless essential; qualifying auto-updates require control; disabling nonessential interaction-triggered motion animation is AAA. A reduced-motion implementation is a design choice/technique, not universal AA proof or a substitute for 2.2.2. If flashing/video occurs inspect its separately applicable SC. |

**E1:** W3C WAI, [*Understanding SC 1.4.10: Reflow*](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), informative WCAG 2.2 Understanding, updated **10 August 2026**; explains that 320 CSS px includes zoomed larger screens, and that 2D exception is local. **E2:** W3C WAI, [*Understanding SC 2.3.3: Animation from Interactions*](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html), informative, updated **16 September 2025**; `prefers-reduced-motion` may be a technique, not universal requirement. Both pages fetched 2026-09-30. Primary N0 controls the SC. Other dates in A-9081–83 are leads, not claims of reinspection here.

## Situated conventions and explanatory practices

| Source title / version & displayed date / URL | Bounded design inference and limitation |

| **S1** GOV.UK Design System, [*Question pages*](https://design-system.service.gov.uk/patterns/question-pages/); live, page date/version **unknown** | In GOV.UK service questions: start one question/page, ask only needed data, back/heading/Continue; grouping related questions when user research supports it. For another service consider focused steps, but number of steps and exact button word depend on tasks. |
| **S2** GOV.UK Design System, [*Navigate a service*](https://design-system.service.gov.uk/patterns/navigate-a-service/); live page update **unknown**, says pattern introduced **August 2024** | Clear end-to-end transaction tends to avoid service nav links; repeated unordered tasks can need top-level links. This does not forbid navigation on commerce discovery or prove findability for a particular audience. |
| **S3** GOV.UK Design System, [*Error summary*](https://design-system.service.gov.uk/components/error-summary/) and [*Recover from validation errors*](https://design-system.service.gov.uk/patterns/validation/); live page updates/edition **unknown** (component history is not page date) | Within this system show summary plus local matching messages, move focus and link to fields; rerender entries; defer most validation until submit, with researched exceptions. A different brand may choose different error layout/timing; disabling HTML5 validation is a GOV.UK implementation convention, not an SC. |
| **S4** GOV.UK Design System, [*Language navigation*](https://design-system.service.gov.uk/components/language-navigation/); **Trial**, live update **unknown** | Offer equivalent key information, use native language names, retain entries and test translations; neither this component nor inferred locale auto-selection translates content. Trial placement is not a universal rule. |
| **S5** GOV.UK Design System, [*Layout*](https://design-system.service.gov.uk/styles/layout/), [*Type scale*](https://design-system.service.gov.uk/styles/type-scale/), [*Colour*](https://design-system.service.gov.uk/styles/colour/); page dates **unknown**; type scale explicitly **GOV.UK Frontend v6.0.0+** | Their single-column-first/two-thirds reading width, responsive type roles, functional color tokens and GOV.UK palette suit services adopting them. For other brands design own semantic tokens/scale, then test zoom, line length, scripts and color pairs. No universal 19px body, 640px breakpoint, 75-char ceiling or borrowed GOV.UK brand. |
| **S6** GOV.UK Service Manual, [*Writing for user interfaces*](https://www.gov.uk/service-manual/design/writing-for-user-interfaces), published **10 October 2017**, last updated **16 April 2018** | In stressed government tasks, direct user language, descriptive headings/errors, restrained tone; for commerce brand voice can be expressive in editorial space while task labels remain clear. No universal ban on humor or evidence that specific wording converts. |
| **E3** W3C WAI, [*Introduction — ARIA Authoring Practices Guide*](https://www.w3.org/WAI/ARIA/apg/about/introduction/) and [*Disclosure (Show/Hide) Pattern*](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/); live, individual dates **unknown** | APG is informative, not a UI design system; disclosure models button + expanded state and Enter/Space, with examples illustrative, not production-ready. Check browser/AT and match interaction; don't turn ordinary disclosure into a complex menu. |
| **E4** W3C Internationalization, [*Declaring language in HTML*](https://www.w3.org/International/questions/qa-html-language-declarations.en); page date/version **unknown**, HTML only | Declare `html lang` and changed-language spans; use `dir` for bidirectional writing when needed. Language declaration is not translation quality, `lang` ≠ text direction. |
| **E5** W3C WAI, [*Involving Users in Evaluating Web Accessibility*](https://www.w3.org/WAI/test-evaluate/involving-users/); first published **November 2005**, content updated **1 June 2021**, links updated **30 April 2024** | Include relevant disabled/AT users in task evaluation; small samples cannot represent all users, and user evaluation alone does not certify WCAG. Observe outcomes before asserting usability. |
