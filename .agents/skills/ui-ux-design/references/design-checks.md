# Context checks: select by task and artifact, not as universal template

Use [evidence map](evidence.md) to trace any cited rule and verify currently applicable edition. This is a design-review aid, not a conformance checklist.

| Design layer | Specify the choice and its competing direction | What can actually be checked |
| --- | --- | --- |
| Task/IA and hierarchy | Entry routes, user's question, labels, primary/secondary actions, return paths; compare guided single-task sequence with browsing/grouped options. Give a sitemap/flow and sample copy, including no-result state. | On paper: task coverage, sequence, labels and proposed links. On prototype: destination/findability and keyboard path. Users: observe actual finding/comprehension. WCAG 1.3.1/1.3.2, 2.4.4/2.4.6, 3.2.3/3.2.4 where applicable. |
| Brand/color/visualization | Semantic tokens for text, surfaces, actions, error and focus; roles for editorial imagery; an alternative identity that still expresses the product. | sRGB contrast for *actual adjacent pairs* (1.4.3, 1.4.11), color not alone (1.4.1); check photo overlays in rendered states. Distinctiveness and mood = expert judgment + user feedback, not ratio. |
| Typography/layout | Text roles, font/script fallback, content width, whitespace, reading order; compare quiet task-first with image-led editorial hierarchy. | Mockup: approximate structure. Rendered UI: 200% text, 320 CSS px equivalent reflow, spacing overrides, long translations; exception for locally essential 2D elements. Check large-text status before using 3:1; no universal font, grid, 75-char or breakpoint. |
| Interaction/responsive | Destinations/navigation, controls, focus path, pointer hit boxes, disclosure behavior, overlays, state retention across window changes. | Prototype: keyboard, trap, visible and unobscured focus, 24 CSS px target-or-exception analysis; orientations, input modes, zoom and hover/focus content. APG disclosure is informative; test semantics with actual browser/AT. |
| Content/language | Required info, native-language choice, locale-specific names/date/address/number formats and full key journey coverage; error, empty, loading, success and offline copy. | Inspect translation with proficient speakers, document/segment `lang`, direction, text expansion, switch state and back navigation. WCAG 3.1.1/3.1.2/3.3.1–3.3.3/4.1.3 apply conditionally; static copy cannot prove implementation or translation quality. |
| Motion/media/performance | Describe onset, purpose, duration, control, static/reduced variant; poster/alt/low-data paths for rich content. | Run prototype to check qualifying 2.2.2 autostart pause and (if aiming AAA) 2.3.3 interaction-motion disable; no performance/bitrate claim without measurement, nor comprehension claim without users. For meaningful imagery/media inspect corresponding text alternatives/captions as applicable. |

**Contrast calculation (opaque sRGB pairs only):** convert each hex byte `c` to `s=c/255`, linearize `v=s/12.92` if `s<=0.04045`, else `v=((s+0.055)/1.055)^2.4`; `L=0.2126R+0.7152G+0.0722B`; ratio `(lighter L+0.05)/(darker L+0.05)`. Use actual composited pixel colors for transparency/photos; never round upward to claim a pass. Formula and exceptions: WCAG 2.2 N0 glossary and E0. Record inputs, text/graphic role, target SC, ratio and what is not measured.

**Review accounting:** separate observations/measurements from expert predictions and unknown user outcomes. Record whether a static spec, running implementation or representative users were available, which locales/browser/AT/viewport combinations were tried, and what reversal signal would change the design.
