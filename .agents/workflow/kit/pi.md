# Pi compatibility (v1)

Run Pi from the installed workspace so its `AGENTS.md` and project `.agents/skills/<name>/SKILL.md` are in scope. In Pi 0.99.1, context files such as `AGENTS.md` load regardless of project trust (unless context loading is disabled), but project `.agents/skills` are trust-gated. In non-interactive print mode, with no applicable CLI override, extension decision, or saved trust decision, the default `defaultProjectTrust: "ask"` skips protected project resources because Pi cannot prompt. For a one-invocation trust decision when those project skills are needed, use `--approve` after deciding to trust the workspace; check the trust behavior of the installed Pi version and any existing trust decision. `--approve` permits Pi to load project resources for that process; it is **not** user approval of a work-unit scope or a workflow checkpoint. Check the matching checkpoint in the root/parent brief under `.agents/workflow/protocol.md` before delegating work. Pi loads a role file with `--append-system-prompt`; OpenCode instead requires the five agent entries pointing to `.agents/roles/*.md` in workspace config.

For example, from the installed workspace, after verifying approval for the named unit/revision, launch a **separate** investigator process with a fresh attempt ID (replace the example IDs, path and question with the actual assignment):

```sh
pi --approve --no-session -p --model opencode-go/gpt-6-luna \
  --append-system-prompt .agents/roles/investigator.md \
  'Investigate U-1234@revision-1 as investigator, attempt A-1234. Read AGENTS.md, .agents/workflow/protocol.md, the unit brief and its matching checkpoint. Check the available project skill list, then read the full .agents/skills/critical-reasoning/SKILL.md, .agents/skills/clear-communication/SKILL.md and .agents/skills/investigate-unit/SKILL.md on demand. Answer the bounded question from the assigned sources. Write only .workflow/attempts/U-1234/A-1234/report.md; return only the compact receipt specified by .agents/workflow/protocol.md.'
```

`-p` prints the final answer and exits; `--no-session` uses a non-persisted in-memory session (it does not guarantee no runtime metadata writes). Replace the example model with one available to your Pi installation. `--append-system-prompt` appends the role file to the system prompt rather than replacing the default; Pi's context-file loading is separate. Supply the actual question, evidence paths, owned paths and stop conditions in the assignment. Inspect the session's available-skills list for **project** skill names and paths, then read the full relevant SKILL.md files when needed. Merely finding or directly reading a skill file on disk does not establish that Pi discovered it as a session resource: the A-9058 trial did the latter without listing project skills, while A-9059 reported both the list and on-demand reads after `--approve`.

This is manual separate-session guidance, not automatic delegated subagent orchestration. The operator checks the worker's report and receipt; the report-only-write boundary is instruction-based, not enforced by the role prompt or Pi project trust. The live trial used Pi 0.99.1 and `--approve` with no explicit `--skill` override; its session-list evidence is the worker's report, not an independent Pi startup/tool trace. Behavior can vary by version, saved/default trust decision and mode. Consult your installed Pi's `docs/cli.md` (invocation, sessions, resources, prompts) and `docs/security.md` (project trust), or the corresponding upstream [CLI](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/cli.md) and [security](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/security.md) docs for your installed version.

For every role, including coordination, require full reads of `.agents/skills/critical-reasoning/SKILL.md` and `.agents/skills/clear-communication/SKILL.md` before workflow work, in addition to the assignment's specialist skills. Start a fresh process after merging skills and inspect both its available-skill context and actual reads; the complete updated source kit has 19 skill entries, but this document establishes no new Pi discovery or loading result. Pass available reader/current-problem and reader-visible definition context with links, as described in the [protocol](../protocol.md#attempts-and-handoff).
